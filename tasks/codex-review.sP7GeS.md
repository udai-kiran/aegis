> `[P1] Version immutable inputs instead of mutating backtest provenance` — A run stores only mutable foreign keys, dates, and overrides; strategy version/code, configuration parameters, and historical bars can all be changed in place. After any such change, a result can no longer be reproduced or reliably attributed, violating the explicit reproducibility and immutable-version requirements. Snapshot version identifiers and dataset/configuration inputs when scheduling a run. > `[P2] Restrict traders from rewriting strategy configuration and promotion state` — The same PATCH grants `TRADER` access to `parameters`, `lifecycle_status`, and `is_active`, with no lifecycle transition validation. I reproduced a trader replacing risk parameters and moving a config directly from `DEVELOPMENT` to `LIVE_FULL` with a 200 response. This bypasses the documented separation between configuration and strategy activation/promotion. > `[P2] Validate strategy PATCH values before reaching PostgreSQL` — `StrategyUpdate` drops all creation-time length and non-null constraints, then assigns values directly before `flush`. Both `{"name": null}` and a 21-character version produced unhandled 500 responses rather than validation errors; arbitrary status strings are also accepted. Mirror the create/model constraints for required update fields. > `[P2] Reject non-finite OHLC prices before persisting them` — The four prices are unconstrained floats. The current parser accepts `NaN`; upload returned 201 and stored it, after which querying that instrument/timeframe returned 500 during JSON serialization. Require finite values and validate OHLC relationships before ingestion. > `[P2] Normalize or reject timezone-naive timestamps before deduplication` — The schema accepts both naive and aware datetimes, while deduplication uses the Python datetime directly. On the default UTC PostgreSQL configuration, `2024-02-01T00:00:00` and `2024-02-01T00:00:00Z` are distinct dictionary keys but the same `timestamptz`; the resulting upsert still raises a cardinality violation and returns 500. Require aware timestamps and normalize to UTC before building conflict keys.
