> `[P1] Enforce actual egress isolation` — `internal` and `execution` are ordinary bridge networks, which provide outbound connectivity by default; their names do not restrict traffic. A compromised `strategy-engine`, API, or database container can therefore contact broker APIs directly, violating the PRD’s execution boundary. Mark the non-egress networks as internally isolated and give external access only to explicitly authorized services. [docker-compose.yml:3](/home/udai/personal/aegis/docker-compose.yml:3), [docker-compose.yml:161](/home/udai/personal/aegis/docker-compose.yml:161), [PRD §63](/home/udai/personal/aegis/aegis_trader_multi_tenant_prd.md:1639). [Docker network behavior](https://docs.docker.com/reference/compose-file/networks/)

> `[P1] Separate the application role from the database superuser` — `POSTGRES_USER` creates a PostgreSQL superuser, and the same credentials are placed in the API gateway’s `DATABASE_URL`. When tenant tables and RLS are introduced, application queries will bypass RLS and all normal privilege checks, defeating the PRD’s defense-in-depth tenancy model. Initialize a distinct least-privileged runtime role instead. [docker-compose.yml:31](/home/udai/personal/aegis/docker-compose.yml:31), [docker-compose.yml:121](/home/udai/personal/aegis/docker-compose.yml:121), [PRD §55](/home/udai/personal/aegis/aegis_trader_multi_tenant_prd.md:1481). [Postgres image role semantics](https://hub.docker.com/_/postgres/), [PostgreSQL RLS behavior](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

> `[P1] Keep development port exposure off the default deployment path` — The documented `docker compose up` command automatically merges this override, publishing PostgreSQL, Redis, MinIO, and the API directly on every host interface. Thus the normal deployment path bypasses the reverse proxy and violates the invariant that only it exposes the API; on a reachable host, the databases are also exposed to the network. [docker-compose.override.yml:1](/home/udai/personal/aegis/docker-compose.override.yml:1), [docker-compose.override.yml:5](/home/udai/personal/aegis/docker-compose.override.yml:5), [.env.example:2](/home/udai/personal/aegis/.env.example:2), [PRD §63](/home/udai/personal/aegis/aegis_trader_multi_tenant_prd.md:1656). [Compose override loading](https://docs.docker.com/compose/how-tos/multiple-compose-files/merge/), [published-port behavior](https://docs.docker.com/get-started/docker-concepts/running-containers/publishing-ports/)

> `[P1] Exclude the real environment file from version control` — The template instructs developers to create `.env`, but the repository has no `.gitignore`, and `git check-ignore` confirms `.env` is not ignored. Following the documented workflow leaves database and object-storage credentials visible to `git add`, creating a direct secret-leak path contrary to PRD §64. [.env.example:1](/home/udai/personal/aegis/.env.example:1), [PRD §64](/home/udai/personal/aegis/aegis_trader_multi_tenant_prd.md:1673)

> `[P1] Restrict Traefik’s Docker API access` — Mounting `/var/run/docker.sock` with `:ro` only makes the socket filesystem mount read-only; it does not restrict Docker API operations sent through it. If the host-facing proxy is compromised, an attacker can control containers and escalate to the Docker host. Use a narrowly authorized socket proxy or another restricted discovery mechanism. > `[P2] Make Redis reachable from its clients` — Protected mode is enabled with neither a bind rule nor authentication, despite the comment claiming a password will be supplied; Compose supplies none, and `REDIS_URL` contains none. Redis therefore accepts the local healthcheck but rejects commands from the API container’s non-loopback address, allowing both Redis and the gateway to be reported healthy while the dependency is unusable. [infra/redis/redis.conf:11](/home/udai/personal/aegis/infra/redis/redis.conf:11), [docker-compose.yml:56](/home/udai/personal/aegis/docker-compose.yml:56), [docker-compose.yml:121](/home/udai/personal/aegis/docker-compose.yml:121). > `[P2] Configure the published HTTPS endpoint` — Port 443 is published and exposed as configurable, but Traefik defines only the `web` listener on port 80; there is no port-443 entry point, TLS router, or certificate configuration. Connections to the advertised HTTPS port will not reach the API. [docker-compose.yml:98](/home/udai/personal/aegis/docker-compose.yml:98), [infra/traefik/traefik.yml:6](/home/udai/personal/aegis/infra/traefik/traefik.yml:6), [.env.example:13](/home/udai/personal/aegis/.env.example:13)

> `[P2] Encode database credentials before constructing a URI` — `POSTGRES_PASSWORD` is interpolated directly into `DATABASE_URL`. Valid strong passwords containing URI delimiters such as `@`, `/`, `:` or `#` produce a malformed or differently parsed connection URL; for example, Compose renders `p@ss:word/with#chars` unchanged. The gateway will fail database authentication once that dependency is exercised. [docker-compose.yml:121](/home/udai/personal/aegis/docker-compose.yml:121), [.env.example:4](/home/udai/personal/aegis/.env.example:4)

> `[P2] Remove fixed container names from scalable services` — Every service declares a global `container_name`. Compose refuses to scale such services beyond one replica, and separate dedicated-tenant stacks on the same host will collide on the same names. This contradicts the PRD’s “one or more containers” architecture and future dedicated Compose deployments. [docker-compose.yml:24](/home/udai/personal/aegis/docker-compose.yml:24), [docker-compose.yml:118](/home/udai/personal/aegis/docker-compose.yml:118), [PRD §60](/home/udai/personal/aegis/aegis_trader_multi_tenant_prd.md:1586), [PRD §61](/home/udai/personal/aegis/aegis_trader_multi_tenant_prd.md:1597).
